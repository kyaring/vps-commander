## 2. 运行版与 891904a 源码的差异

- 二进制标记 dirty，说明构建时工作区有未提交改动，内容无法从二进制还原。
- 字符串抽查（二进制命中数 / 源码命中文件数）：`devtask` 0/0、`/api/v1/devtasks` 0/0、`emit_event` 0/0、`developer` 0/0、`wecom_bot` 0/0、`notification_offline_states` 0/0；`oauth_clients`、`/oauth/authorize`、`events:emit`、`resource_metadata`、`VPS_COMMANDER_PUBLIC_URL`、`exit_nonzero` 两边都有。
- 已实测确认：用同样参数（go1.24.4、CGO_ENABLED=0、-trimpath、-ldflags "-s -w"）在本机重新构建 891904a，产物与运行版大小完全相同（14303416 字节），全部字符串中只有 build id 和 vcs.modified/+dirty 标记不同。所以 dirty 只是工作区里的非代码文件，运行代码就是 891904a = v1.1.35。
- DevTask、离线持久化、企业微信机器人渠道、开发者标签等 10-11 晚以后的工作都不在运行版里。
- 数据库是新建的（23 张表，无 devtask_* 表）；旧库 /opt/vps-commander/data/commander.db（wjyhk）里的令牌、渠道、模板、DevTask 记录和 diff_md 都不在这里。
