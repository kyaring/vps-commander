任务：修复取播放地址的 standard 兜底被变量遮蔽而失效（go vet 自赋值）
编号：T-20261012-01
开发者：flash（global:deepseek-v4.1-flash，经 DevTask）
分支：基于 main（3e2d658），由 DevTask 新建
约束：不 push、不打 tag、不部署
改动范围：允许 cmd/server/main.go；禁止 deploy/ bin/ staging/ go.mod go.sum internal/

一、问题
1. 现象：go vet ./... 报 cmd/server/main.go:2411:4: self-assignment of p to p，项目基线验收不过。
2. 原因：取播放地址依次尝试 lossless → exhigh → standard。standard 这一步写成 `if p, e := s.m.GetPlayURL(ctx, src, rid, "standard"); e == nil { err, p = nil, p }`，`:=` 新建了局部 p 遮蔽外层 p，赋值只作用于局部变量。
3. 影响：lossless 和 exhigh 都失败、standard 成功时，外层 p 仍是失败结果，任务报 "play url unavailable"，standard 兜底从未生效。

二、要求
1. 只改这一处：standard 成功（e == nil）时，外层 p 等于 standard 的返回值，外层 err 置为 nil。写法示例：`if p2, e := s.m.GetPlayURL(ctx, src, rid, "standard"); e == nil { p, err = p2, nil }`。
2. 其余逻辑（lossless、exhigh 顺序，后续 "play url unavailable" 判断）一字不改。
3. go vet ./... 无任何输出。
不做：不重构该函数，不改其他文件，不删除 cmd/server 下的 main.go.before-* 备份文件。

三、测试
s.m 是具体类型 *adapter.Manager，无法打桩，本任务不新增测试（OPC 已知悉）；由审核方代码审查确认第二节 1–2，并以 go vet 结果验证第 3 条。
