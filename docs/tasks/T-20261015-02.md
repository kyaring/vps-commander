## 一、问题（Hark 10-15 05:54 负载考察）
1. cmd/hub/main.go:170 的 http_request 日志只记了 client_ip。所有流量都经过反代 192.168.20.1，4 个 agent 同时在跑时，401、405、30 秒的长请求都分不清是谁发的。
2. /panel/api/audits 每页 100 条，单次返回就有 127KB，面板每刷新一次都要拉这么多。分页本身已经有（limit、cursor），问题出在单条记录太大。

## 二、要求
1. **http_request 日志增加调用方**：鉴权成功的请求，增加 `actor_type`（panel、api_token、system、oauth 等，按现有 Principal.Type）和 `actor`（令牌的名字或 id，例如 hark-2；面板会话写 panel）。鉴权失败或者匿名的请求，写 `actor=-`。
   - 实现提示：日志中间件在外层，Principal 是在内层才放进 context 的。可以在外层先放一个可写的 holder，等鉴权成功后填进去；也可以换别的办法，但不能让鉴权再执行一遍。
   - **绝不**记录令牌值、令牌哈希、Authorization 头、cookie 或 OAuth code。
   - MCP 请求另加 `mcp_tool`（如果能拿到工具名）。不要记录参数。
2. **audits 列表瘦身**：
   - /api/v1/audits 和 /panel/api/audits 的列表响应里，超过 256 字节的长文本字段（命令、输出摘要、错误等，以实际 schema 为准）截断，并附带 `truncated: true`；
   - 新增详情接口 `GET /api/v1/audits/{id}` 和 `/panel/api/audits/{id}`，返回完整记录，权限与列表相同；面板点击某一行时再拉详情；
   - export.csv 保持完整、不截断；
   - 目标：用测试夹具造 100 条、每条命令长 4KB 的记录，默认页的响应必须 ≤ 48KB。
3. 面板 app.js 改为点击行时拉详情；列表里截断的字段末尾显示「…」。

## 三、测试
- 日志：用 slog 的测试 handler 截获日志，断言以下几点：
  1. api_token 请求的 actor 是令牌名；
  2. 401 请求的 actor 是 -；
  3. 用一个哨兵令牌值发请求，日志全文里不能出现这个值，也不能出现它的哈希。
- audits：截断与 truncated 标记、详情接口返回全文、详情接口没有权限时返回 401/403、export.csv 不截断、上面的 48KB 体积断言。
