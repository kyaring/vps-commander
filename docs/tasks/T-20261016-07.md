## 1. 背景
Hark 于 main a434168 核对。
- 现象：OPC 在 Grok App 里添加自定义连接器 https://vcs.king.nyc.mn/mcp，跳到浏览器后不出现授权页，直接弹回 App。
- 证据：journalctl -u vps-commander-hub 在 10-16 19:31、19:32、19:37 三次的顺序都是：well-known 两个端点 200，然后 GET /oauth/authorize 返回 302，之后没有 /oauth/token。client_id 和 redirect_uri 正确（错的话 oauthClientAndRedirect 返回 400，不会是 302），回调地址 https://grok.com/connectors-oauth-exchange-code/ 已登记。
- 根因（推断；日志不记 query，所以无法确认是哪一项）：internal/mcp/oauth_flow.go:243-245 要求请求必须带 resource 且等于 OAuthResourceURL()，否则返回 invalid_target；:248-250 parseOAuthScopes 遇到空 scope 返回 invalid_scope（oauth_flow.go:108-111）。两种情况都走 fail() 用 302 带错误码回去。Grok 很可能没带 resource 或 scope。另外 /.well-known/oauth-authorization-server 没有 scopes_supported，客户端无从得知该请求哪些 scope。
- 现状：所有 fail() 分支都不写日志，排障只能靠推断。

## 2. 要求
1. resource 缺失（参数不存在或为空字符串）时，取 OAuthResourceURL() 作为默认值，继续往下走；resource 存在但与 OAuthResourceURL() 不一致的，仍然返回 invalid_target。OAuth 未启用（enabled=false）的行为不变。
2. scope 缺失或为空白时，默认取受支持的全部 scope，即与 /.well-known/oauth-protected-resource 的 scopes_supported 是同一集合，且不含 admin。scope 非空时，现有解析规则（拒绝 admin、拒绝重复、忽略未知、全部未知则 invalid_scope）完全不变。默认之后，授权页的令牌候选和 scope 取交集的逻辑不变：不能让任何令牌拿到它本身没有的 scope，含 admin 的令牌仍然不出现在候选里。
3. /.well-known/oauth-authorization-server 增加 scopes_supported 字段，取值与第 2 条的默认集合相同，要求来自同一个变量或函数，不能各写一份。
4. beginOAuthAuthorization 里每一个 fail() 分支以及两个 400 分支，都用 slog 记一条 WARN：msg=oauth_authorize_rejected，字段为 code（错误码）、check（哪项校验，例如 resource_mismatch、scope_empty_after_filter、pkce、state、duplicate_param、client_or_redirect）、client_id、has_resource、has_scope、has_state、has_challenge（布尔值）。严禁记录 state、code_challenge、redirect_uri 的完整 query、scope 原文以外的任何参数值；scope 原文也不记。
5. 第 1、2 条使用了默认值时，记一条 INFO：msg=oauth_authorize_defaulted，字段为 client_id、defaulted_resource、defaulted_scope（布尔值）。
6. token 端点（oauth_flow.go:481 起）不改：它已经允许 resource 为空，并与 rec.Resource 比较。

不做：DCR（动态注册）；改 token 端点；放宽 redirect_uri 的精确匹配；改授权页 UI；改任何现有测试。

## 3. 测试（只放在新文件 internal/mcp/oauth_authorize_defaults_test.go）
1. 不带 resource、scope 合法：进入授权页（200，不是 302）。
2. 不带 scope、resource 合法：进入授权页，候选令牌的 scope 是「默认集合 ∩ 令牌自身 scope」。
3. 两者都不带：进入授权页。
4. resource 不一致：302 且 error=invalid_target，并产生 oauth_authorize_rejected 日志，check=resource_mismatch。
5. scope 只含 admin：仍然被拒。只含 admin scope 的令牌，在默认 scope 下也不出现在候选里。
6. AS 元数据含 scopes_supported，且等于 PR 元数据的 scopes_supported。
7. 日志断言：拒绝日志里不含测试用的 state 值和 challenge 值（用独特字符串检索）。
8. 端到端：缺省 resource 走完授权，再到 /oauth/token 换出令牌，返回的 resource 等于 OAuthResourceURL()。
反向验证：分别撤掉第 1 条和第 2 条的默认逻辑，测试 1、2 必须变红，之后还原。在交付说明里贴出两次变红的输出。
