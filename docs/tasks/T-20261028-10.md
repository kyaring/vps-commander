一、目标
1. 主密钥：环境变量 VPS_COMMANDER_PROVIDER_KEY，32 字节，base64 或 hex 编码，写在 /etc/vps-commander/hub.env（root，600）。未设置时：可以登记提供商的非密钥信息，但不能保存或取出 key，接口返回 503 provider_key_not_configured。主密钥不进仓库、数据库或日志；启动日志只能写“configured: true/false”。
2. 存储：表 dev_model_providers：id（^[a-z0-9_-]{1,32}$，主键）、display_name、enabled、sealed_blob（BLOB，AES-256-GCM 密文，AAD 为 provider id）、key_set（0/1）、created_at、updated_at。明文的 base_url 与 api_key 只在内存中短暂存在；sealed_blob 解密后的 JSON 为 {"base_url":"...","api_key":"..."}。
3. 管理接口（admin，DEVTASK_ENABLED 门控，沿用 D2）：
   - GET /api/v1/devtask-providers：返回 id、display_name、enabled、key_set。永不返回 base_url 或 api_key，也不返回任何掩码片段。
   - PUT /api/v1/devtask-providers/{id}：写入 display_name、enabled，以及可选的 base_url 与 api_key。
     - base_url 必须是 https:// 开头的绝对 URL；
     - api_key 为空字符串或字段缺省表示不修改；要清空 key 必须显式发送 clear_key=true；
     - 写审计 action=devtask_provider_update，详情只含 id、enabled、key_set 的变化和“base_url 已修改”“api_key 已修改”，绝不含值。
   - 不实现“测试连接”（Hub 不调用模型；测试连接另开卡，由 runner 完成）。
4. 白名单关联：白名单条目 <provider_id>:<model> 写入时，provider_id 必须已登记且 enabled，否则 400（沿用 T-20261028-04 的白名单接口）。
5. runner 取凭据接口（本卡实现，runner 侧在 T-20261028-11）：
   - POST /api/v1/devtask-runner/credentials，body 为 {"task_id":"...","lease_id":"...","provider_id":"...","model":"..."}；
   - 只接受 runner 的命名令牌（scope devtask:run），且令牌的 runner 身份与任务的 claimed_by 一致；
   - 校验：任务存在、状态为 running、lease 未过期且与任务的 lease 一致、model 在白名单内且其 provider 与 provider_id 一致、provider enabled 且 key_set=1；任一不满足返回 403 或 409，不返回任何凭据；
   - 只有 Hub 认为请求经 HTTPS 到达时才返回凭据：X-Forwarded-Proto 必须为 https，或请求来自 127.0.0.1；否则 403（说明：X-Forwarded-Proto 可以被局域网内的客户端伪造，本条是辅助防护，不是完整保证，记录在交付说明中）；
   - 成功返回 {"base_url":"...","api_key":"..."}，响应头 Cache-Control: no-store；写审计 action=devtask_credential_issue，详情含 task_id、provider_id、model、runner 身份，不含值；
   - 每次取出都写审计，包括被拒绝的请求（action=devtask_credential_denied，详情含拒绝原因码）。
6. 管理面板（internal/web 不在本卡范围，只输出接口契约写入 docs/api.md）：api_key 为仅写入字段，前端显示“已配置”或“未配置”，修改时重新输入。
