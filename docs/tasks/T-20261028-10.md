一、目标
1. Hub 只保存非密钥的提供商登记：provider_id（^[a-z0-9_-]{1,32}$）、display_name、enabled。URL 和 Key 不进入 Hub 的数据库、接口、日志或审计。
2. 白名单条目沿用 `<provider_id>:<model>` 格式（如 global:deepseek-v4.1-flash）。写入白名单时，provider_id 必须存在且 enabled，否则 400。
3. 管理员接口（requireScope admin，DEVTASK_ENABLED 门控，沿用 D2）：
   - GET /api/v1/devtask-providers：列出登记项，附 configured 字段；configured 由 runner 上报得到，本卡不实现上报，固定返回 unknown；
   - PUT /api/v1/devtask-providers：整体替换登记（id、display_name、enabled）；写审计，含旧值与新值（不含密钥，本卡无密钥字段）。
4. runner（cmd/devtask-runner、internal/devtask）按提供商 ID 解析配置：
   - 每个提供商读取 MODEL_<ID大写>_BASE 与 MODEL_<ID大写>_KEY（ID 中的 - 转为 _）；
   - 任务的 provider 缺少 BASE 或 KEY，或该提供商在 Hub 登记中 enabled=false：任务进入 blocked_model，error_code 为 provider_not_configured，不尝试其他提供商；
   - 不保留 D5 的单一 MODEL_API_BASE/MODEL_API_KEY 兜底，除非 OPC 另行批准。
5. 日志与审计：runner 的日志只能输出 provider_id 与模型名，不输出 BASE 和 KEY。新增测试用例扫描全部输出，确认不含 KEY 的值。
