二、要求
1. 新渠道类型 wecom_bot：
   a. storage 类型白名单加入 wecom_bot。凭据只放进加密 secrets：{"webhook_url": "..."}；URL 必须是 https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<非空>，否则 400。config 只允许 {"mentioned_list": [...]}（可选，最多 10 个、每个最长 64 字符），其他键一律拒绝。新建时必须带 secrets，更新时不带 secrets 就保留原值（跟 telegram_bot 一样）。
   b. 渠道视图（GET channels）：credentials_configured=true，不返回 URL 和 key；safeNotificationChannelConfig 只回显 mentioned_list。
   c. outbox 发送：模板 format=markdown 时用 msgtype=markdown，否则 msgtype=text（text 附带 mentioned_list）。企业微信即使出错也回 HTTP 200，所以要解析响应体：errcode==0 才算成功；errcode!=0 记为失败（按 4xx 处理，不重试），last_error 只写 "wecom errcode=<n>"，不写 errmsg 原文，也不写 key。HTTP 5xx 和超时按现有规则重试。不跟随重定向（沿用 doNotificationRequest）。
   d. 失败信息、审计、日志、投递记录里都不能出现 key 或完整 URL。
   e. channels/test 支持 wecom_bot。
2. 内置 default 模板：在 migrateNotificationV1 的 builtins 里加一个 id=builtin-default，event_type=custom.default，severity=P3（不能写 *：notification_events.go:199 会拒绝发送 severity=* 的模板，这个文件也不在本卡改动范围内。用 P3 的话，events:emit 可以发 P3/P4，发 P2 算升级、要 admin，P1 也要 admin，都是现有规则），format=text，title_template={{title}}，body_template={{message}}，variables_json=["title","message"]，enabled=true。用 INSERT OR IGNORE 的方式写入（跟现有 builtins 一样），不覆盖用户改过的同 id 模板。/api/v1/events 可以用 template_id=builtin-default 发事件（events:emit 就够，P1 和升级严重级别的现有限制不变）。
3. 旧 webhook 写接口返回 410：
   a. /api/v1/notifications/webhook/update 和 /webhook/delete 对任何方法都返回 410 Gone，正文 JSON 为 {"error":"legacy webhook API removed; use /api/v1/notifications/channels"}，并写一条审计（action notification_setting_legacy_gone，result 走现有规则），不能再改 webhook_targets。
   b. GET /api/v1/notifications/webhooks 和 /webhook/test 保持原样（只读和测试发送）。
   c. notify.go:148 OpenClaw 自动导入走的是 storage，不经过 API，不改。
   d. 面板：app.js 里旧 webhook 的保存和删除按钮去掉或禁用，并提示改用新渠道；新渠道表单的类型下拉加「企业微信机器人 (wecom_bot)」，填 webhook_url（password 输入框，编辑时留空就保留）和 mentioned_list。index.html 的审计表一列都不能动（T-07 的测试会检查）。
