### 第二部分：新增取凭据接口（核心）

**接口**：`POST /api/v1/devtasks/{id}/credentials`

**鉴权**：`requireScope("devtask:run")`，且**必须是该任务的当前租约持有者**。

**必须同时校验以下四项，任一不满足即拒绝**（对应 `docs/devtask-spec-amendment-1028.md` 的「前提 1」）：

1. **租约有效**：任务状态为 `running`，`claimed_by` 等于调用方令牌 id，`lease_until > now`。
   - 租约过期 → `409 Conflict`，响应体 `{"error":"lease_expired"}`。
   - 非持有者 → `403 Forbidden`，`{"error":"not_lease_owner"}`。
2. **模型在白名单内**：`task.Model` 必须存在于 `devtask.allowed_models`（复用现有 `GetDevTaskAllowedModels`，fail-closed）。
   - 不在白名单 → `409 Conflict`，`{"error":"model_not_allowed"}`。
3. **provider 已启用**：从 `task.Model` 解析 provider id（格式 `<provider_id>:<model>`），该 provider 必须存在且 `Enabled=true`。
   - 未登记或未启用 → `409 Conflict`，`{"error":"provider_unavailable"}`。
4. **调用方是 runner 命名令牌**：`Principal.Type == "api_token"`，且不是 legacy key。

**成功响应**（`200`）：
```json
{"base_url":"https://...","api_key":"..."}
```
- `base_url` 与 `api_key` 来自解密后的 sealed blob。
- 响应头必须设 `Cache-Control: no-store`。
- **不得**在响应中返回 provider 的其他字段。

**审计**（对应「前提 2」）：
- 每次调用写一条审计，`action=devtask_credentials`，`target=<provider_id>`，`command` 只写 `task=<task_id> model=<model>`。
- **审计绝不记录 key 值**：不得记录明文、截断、哈希、前缀、长度。
- 失败也要写审计，`result=denied` 或 `error`，`error_msg` 只写错误码（如 `lease_expired`），不带任何凭据片段。

### 第三部分：白名单绑定校验

在 `devtask.allowed_models` 的写入路径（现有 `PUT /api/v1/devtask-settings`）增加校验：

- 每个白名单条目必须形如 `<provider_id>:<model>`。
- 解析出的 `provider_id` 必须**已登记**（`GetDevProvider` 成功）且 **`Enabled=true`**。
- 不满足 → `400 Bad Request`，`{"error":"provider_not_registered","provider":"<id>"}`。
- 校验必须在写库**之前**完成，不得出现部分写入。

### 第四部分：文档

- `docs/api.md`：新增 `POST /api/v1/devtasks/{id}/credentials` 段落，写明四项校验、响应字段、`no-store`、审计动作、四种错误码。
- `docs/devtask.md`：补充「runner 如何取凭据」一节，写明只在内存使用、不落盘、取不到时进入 `blocked_model` 状态、不切换其他模型。
