## 背景
exec_command 默认 30 秒、最长 300 秒，`go test -race ./...` 这类长任务无法通过 MCP 跑完；超时后调用方也不知道命令是死了还是还在跑。OPC 06:35 定：用 start + status 两步，不依赖 MCP tasks（实验特性）。

## 必改
A. **接口**：新增异步启动和查询两种能力。具体做成 exec_command 的参数还是新增工具由开发者决定，但要在交付说明里写明对 tools/list 的改动内容。至少包括：启动（返回 job_id）、查询状态（running / exited / killed / expired，加上 exit_code 和 T-01 的统一返回字段，输出走 spill 文件）、取消。
B. **可见性**：job 只有创建它的令牌能查询或取消，其他令牌一律返回不存在（不泄露 job 是否存在）。
C. **名额**：运行中的 job 占用该令牌的并发 exec 名额，直到结束；不另设一套上限。名额满时启动返回明确错误。
D. **生命周期**：job 最长运行时间设上限（建议 60 分钟，超时 kill，状态记为 killed）；结束后保留状态和输出 24 小时（与 spill TTL 一致），之后状态为 expired；Hub 重启后，运行中的 job 状态要能如实反映（标记为 lost 或 killed，不能一直显示 running）。
E. **审计**：job 结束时补记审计（actor、device、命令摘要、exit_code、耗时），即使客户端早已断开；启动和取消也要记录。
F. **同步 exec 超时留痕**：现有同步 exec 超时时，返回中明确写出 timeout，并在审计中记为 timeout。
G. **tools/list 测试**：按 T-01 的哈希和字节数测试更新哈希；交付说明写明 old → new 的哈希与字节数（≤ 10240）。
H. **文档**：docs/api.md 和 docs/client-skill/SKILL.md 写明什么时候用异步（预计超过 30 秒的命令）以及如何轮询。

## 测试
1. 启动一个 sleep 后输出的命令：查询先是 running，结束后为 exited，exit_code 和输出正确（输出可从 spill 文件读到）。
2. 另一个令牌查询或取消同一个 job：返回不存在。
3. 名额：job 运行期间，同令牌的并发 exec 计数包含它；名额满时启动被拒。
4. 取消：状态变为 killed，进程确实被结束（检查子进程）。
5. 超过最长运行时间：自动 kill。
6. 客户端断开后 job 结束，审计里仍有结束记录。
7. 同步 exec 超时：返回和审计里都标明 timeout。
8. 模拟重启后，原来 running 的 job 不再显示为 running。
