一、背景
1. 生产 Hub 当前运行的是 891904a（v1.1.35）的二进制，sha256 1078ca6b937a4d506e95f8de362ede7ac4cb860b52aebd528b6807ce1443f3b2，这个文件来自旧机，在新机上无法复现。
2. 891904a..8cbd273 之间没有改动 internal/ cmd/ web/ go.mod（只改了脚本和文档），所以新二进制在功能上等同于现网版本，不涉及数据库迁移。本次目的就是把生产换成“仓库可复现的二进制”，同时把部署链路真实跑一遍。
3. 风险：重启期间 Hub 约中断数秒，所有 MCP/REST 会话和 agent 连接会断开后重连。部署命令必须不依赖 Hub 本身的会话（见第 4 步）。

二、步骤
1. 前置检查（任一不满足就停下报告）
   - cd /root/work/vps-commander && git status --porcelain 为空，HEAD = 8cbd273（git rev-parse --short HEAD）。
   - systemctl is-active vps-commander-hub = active；curl -s http://192.168.20.132:9521/healthz 返回 {"status":"ok"}。
   - sha256sum /opt/vps-commander/vps-commander-hub 等于背景第 1 条的值（不等就停，说明生产被别人动过）。
   - df -h /opt 剩余 > 1G；sqlite3、curl、python3 都在。
2. 构建两次，确认可复现
   sh scripts/release-build.sh                                # 默认输出 /root/work/release/8cbd273xxxxx/
   sh scripts/release-build.sh --out /tmp/vc-rebuild-check
   两次 BUILD OK 的 sha256 必须相同，不同就停。然后 rm -rf /tmp/vc-rebuild-check。
   记下 HASH 和 BIN=/root/work/release/<12位>/vps-commander-hub。
3. dry-run
   sh deploy/deploy-hub-local.sh "$BIN" --sha256 "$HASH" --dry-run
   输出必须指向 /opt/vps-commander、/opt/vps-commander/data/commander.db、vps-commander-hub、http://192.168.20.132:9521/healthz。环境里不得设置任何 VC_* 变量（env | grep ^VC_ 为空）。
4. 正式部署（只执行一次）
   为了不受 Hub 重启影响，用独立的 systemd 单元运行，日志落盘：
   systemd-run --unit=vc-deploy-T-20261014-01 --collect --wait \
     -p StandardOutput=file:/root/work/release/deploy-T-20261014-01.log \
     -p StandardError=file:/root/work/release/deploy-T-20261014-01.log \
     /bin/sh /root/work/vps-commander/deploy/deploy-hub-local.sh "$BIN" --sha256 "$HASH"
   （HASH、BIN 写成实际值。）然后 cat 这份日志：
   - 最后一行是 DEPLOY OK <HASH> backup=<dir> → 继续第 5 步。
   - ROLLBACK OK → 停下，报告日志和 journalctl -u vps-commander-hub -n 50 --no-pager（不得含密钥；若有疑似敏感内容先打码）。
   - ROLLBACK FAILED 或无输出 → 立即执行第三节的手动回退，然后报告。
5. 部署后验证
   - sha256sum /opt/vps-commander/vps-commander-hub = HASH；权限 -rwxr-xr-x root。
   - systemctl is-active = active；ActiveEnterTimestamp 是刚才的时间；NRestarts 没有持续增长（隔 60 秒看两次）。
   - curl healthz = {"status":"ok"}；公网 curl -s -o /dev/null -w '%{http_code}' https://vcs.king.nyc.mn/healthz 返回 200。
   - 备份目录里有 vps-commander-hub（sha256 = 背景第 1 条）和 commander.db；sqlite3 <备份>/commander.db "PRAGMA integrity_check;" = ok。
   - journalctl -u vps-commander-hub --since "<部署时间>" --no-pager | tail -30，没有 panic/fatal 等启动错误（只报告是否有，不贴整段日志）。
   - 节点 agent 已重新上线（Hub 的节点列表或 agent 日志能证明即可）。

三、手动回退（只在自动回退失败或第 5 步验证失败时执行，执行前后都要报告）
   B=<备份目录>
   cp "$B/vps-commander-hub" /opt/vps-commander/vps-commander-hub.new && chmod 0755 /opt/vps-commander/vps-commander-hub.new && mv -f /opt/vps-commander/vps-commander-hub.new /opt/vps-commander/vps-commander-hub
   systemctl restart vps-commander-hub && sleep 3 && curl -s http://192.168.20.132:9521/healthz
   数据库不回滚（本次代码没有改 schema）。如果怀疑数据库损坏，只报告，等 OPC 决定，不得自行 .restore。

- 服务 active，内网和公网 healthz 都正常，备份完整并通过 integrity_check。
- 仓库没有改动：git status --porcelain 为空，HEAD 仍是 8cbd273。
