## 一、背景
1. 非登录 shell 的默认 PATH 是 `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin`，其中**没有** `go` 与 `gofmt`：实测 `/usr/local/bin` 与 `/usr/bin` 下都没有这两个可执行文件，它们只在 `/usr/local/go/bin`。
2. 因此**每条用到 go/gofmt 的命令都必须自己 `export PATH=/usr/local/go/bin:$PATH`**，否则报 `not found`。这个坑已造成 **4 次阻塞**：T-20261014-18（acceptance.sh 报 `gofmt: not found`）、T-20261014-30（build-info 核验报 `go: not found`）、T-20261014-31（格式化报 `/usr/bin/gofmt` 不存在），以及更早的同类问题。
3. 根治办法：把 `go` 与 `gofmt` 软链到**已经在默认 PATH 里的** `/usr/local/bin`。此后任何 shell 无需 export 即可使用。

## 二、要求（每步只执行一次，结果不符预期就停下报告，不要重试）
0. 前置检查（任一不满足就停下报告）
   - `systemctl is-active vps-commander-hub` 输出 `active`。
   - `ls -l /usr/local/go/bin/go /usr/local/go/bin/gofmt` 两个文件都存在且可执行。
   - `ls /usr/local/bin/go /usr/local/bin/gofmt` **都不存在**（若已存在就停下报告，**不要覆盖**）。
1. 备份数据库（在线）：`B=/opt/vps-commander/backup-pre-T32-$(date +%Y%m%d%H%M%S); mkdir -m 700 "$B"`；`sqlite3 /opt/vps-commander/data/commander.db ".backup '$B/commander.db'"`；`PRAGMA integrity_check` 必须 `ok`；权限 600。
2. 建软链：`ln -s /usr/local/go/bin/go /usr/local/bin/go`、`ln -s /usr/local/go/bin/gofmt /usr/local/bin/gofmt`
3. 验证（**关键：不要显式 export PATH**）：
   `env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin sh -c 'command -v go; command -v gofmt; echo OK'`
   必须打印两个**可解析路径**（应分别为 `/usr/local/bin/go`、`/usr/local/bin/gofmt`）并输出 `OK`，**不得出现 `not found`**。
   ⚠️ **不要用 `gofmt -l /dev/null` 做验收**：gofmt 会把 `/dev/null` 当 Go 源文件解析并必然报 `expected 'package', found 'EOF'`（退出码 2），看着像失败。T-20261014-32 首轮正是被这条命令误判成受阻的（卡修 1 次）。
4. 只读核对：`ls -l /usr/local/bin/go /usr/local/bin/gofmt` 是指向 `/usr/local/go/bin` 的软链；服务 active、`NRestarts=0`、启动时间未变；`/usr/local/go` 目录内容未被改动。
