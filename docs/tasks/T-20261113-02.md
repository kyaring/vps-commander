## 二、根因（四个独立问题）

### 2.1 `toolArgKinds` 表缺少 dev_task_* 的参数类型

`internal/mcp/args_validate.go:13-20` 的 `toolArgKinds` map 是参数类型校验表，`validateToolArgs` 靠它拒绝类型错误的参数。D4 新增的参数一个都没登记。

缺失 11 个参数（schema 声明的类型）：
```
task_id         string
project         string
title           string
spec_md         string
model           string
status          string
note            string
allowed_paths   array
forbidden_paths array
accept_cmds     array
after_seq       integer
```
（以 `internal/mcp/devtask_tools.go` 中各工具 `InputSchema` 的实际声明为准，逐项核对，不要漏也不要多。）

### 2.2 annotations 在 dev_task_* 追加之前就被应用了（顺序 bug）

`internal/mcp/mcp.go:1253-1257`：
```go
for i := range tools {
    a := annotationsFor(tools[i].Name)
    tools[i].Annotations = &a
}
tools = appendDevTaskTools(ctx, tools)   // ← 追加发生在赋值之后
```
`appendDevTaskTools` 追加的 7 个工具因此永远拿不到 annotations。

**修复要求**：把 `appendDevTaskTools` 的调用**移到 annotations 赋值循环之前**，保证所有工具（含 dev_task_*）都经过 `annotationsFor`。

### 2.3 三个 dev_task_* 工具描述过短

`TestToolMetadataComplete` 要求描述 ≥20 字符（`knownShortDescriptions` 为空 map，当前无豁免）。

| 工具 | 当前 | 处理方式 |
| :--- | ---: | :--- |
| `dev_task_cancel` | 8 字符 | **扩写描述**至 ≥20 字符 |
| `dev_task_list` | 12 字符 | **扩写描述**至 ≥20 字符 |
| `dev_task_logs` | 16 字符 | **扩写描述**至 ≥20 字符 |

**优先扩写描述**（对使用者更友好），不要往 `knownShortDescriptions` 里加豁免。

### 2.4 `tools/list` 哈希基线未更新

`internal/mcp/tools_list_hash_test.go:21` 的 `toolsListBaselineSHA256` 仍是旧值 `6a1767c3...`。D4 新增 7 个工具后应为 `c47c81ef...`（11447 字节）。

**修复要求**：在**其他三项修完之后**，用测试输出的新哈希更新基线。更新时在提交信息里写明「基线随 D4 新增 7 个 dev_task_* 工具更新」。

**OPC 裁定（2026-11-13）**：
- `toolsListMaxBytes` 由 `10240` 调整为 **`16384`**（D4 新增 7 个工具后实际输出 12273 字节，超出旧上限；OPC 已批准新上限）。

## 三、dev_task_* 工具的 annotations 归类（按语义判定）

`annotationsFor` 的现有三张表：`readOnlyTools`（只读）、`destructiveTools`（改状态）、`localTools`（只动 Hub 会话状态）。

按各工具实际行为归类，**必须逐条核对 `internal/mcp/devtask_tools.go` 的实现**后再填：

| 工具 | 建议归类 | 依据（需自行核实） |
| :--- | :--- | :--- |
| `dev_task_list` | `readOnlyTools` | 只列出任务 |
| `dev_task_status` | `readOnlyTools` | 只查询单个任务 |
| `dev_task_diff` | `readOnlyTools` | 只读 diff |
| `dev_task_logs` | `readOnlyTools` | 只读日志 |
| `dev_task_dispatch` | `destructiveTools` | 创建任务 |
| `dev_task_revise` | `destructiveTools` | 改变任务状态 |

**注意**：dev_task_* 会通过 Hub 触达节点/外部模型，因此**不应加入 `localTools`**（`openWorldHint` 应为 `true`）。若你核实后认为某个工具语义不同，在交付说明中写明理由。
