## 一、背景
1. `docs/process/acceptance.sh` 直接调用 `gofmt`、`go vet`、`go build`、`go test`，但**没有自兜底 PATH**。节点上非登录 shell 的 PATH 里没有 go（docs/recovery/REVIEWER-PLAYBOOK.md:19 已记载），因此只要调用方忘了 export PATH，由 `check-task.sh` 调起的 `acceptance.sh` 就会失败。
2. 2026-10-14 07:02 T-20261014-18 实际踩到：`check-task.sh` 输出 `✗ 验收命令失败（docs/process/acceptance.sh）: gofmt: not found`，导致该卡误报受阻（根因见交接文档与 docs/recovery/REVIEWER-PLAYBOOK.md 第 7 节）。
3. 现有规避只停留在文档层面（REVIEWER-PLAYBOOK.md 第 7 节加了「跑 check-task 前先 export PATH」），根因未治：验收脚本依赖调用方环境。
4. `docs/process/check-task.sh` 头部写明「副本由 dev-process/sync.sh 生成，勿直接修改」，所以本卡不改它，只让 `acceptance.sh` 自兜底。

## 二、要求
1. 新增 `docs/process/go-env.sh`：只做一件事——确保 `go` 在 PATH 上。逻辑：若 `command -v go` 已有则直接返回；否则依次探测候选目录，把第一个含可执行 `go` 的目录前置到 PATH 并 export；全部找不到则打印明确错误（必须含字符串 `go toolchain not found`）并 `exit 1`。候选列表用变量暴露，例如 `GO_ENV_CANDIDATES="${GO_ENV_CANDIDATES:-/usr/local/go/bin:/usr/lib/go/bin:/opt/go/bin}"`。
2. `go-env.sh` 必须能被 POSIX sh 以 `.` 方式 source：只用 POSIX sh 语法（不得用 bash 专有语法如 `[[`、数组、`${x^^}`）；被 source 时不得 cd、不得输出多余内容、不得有其它副作用。
3. `docs/process/acceptance.sh` 在 `cd` 到仓库根之后、第一次调用 `gofmt` 之前 source 该文件：`. "$(dirname "$0")/go-env.sh"`。除此之外不改 `acceptance.sh` 的验收内容（仍是 gofmt/vet/build/test/git diff --check）。
4. 新增 `docs/process/test_go_env.sh`（用 `sh` 可运行），至少断言两件事：
   - 候选目录可用时能兜底成功：以 `PATH=/usr/bin:/bin` 运行，`go-env.sh` 被 source 后 `command -v go` 必须成功；
   - 候选目录全部不可用时明确失败：以 `GO_ENV_CANDIDATES=/nonexistent` 运行，必须输出含 `go toolchain not found` 的错误并以非 0 退出。
   脚本自身在全部断言通过时退出码为 0，失败时为非 0。
5. 若 `docs/process/PROJECT-PROFILE.md` 记录了验收命令的调用方式，同步补一句「`acceptance.sh` 会自兜底 go PATH」。
6. 不做：不改 `check-task.sh`、不改任何 Go 代码、不改 `scripts/`、不改 `docs/tasks/` 与 `docs/recovery/`、不动生产、不给 `check-task.sh` 或其它脚本加 PATH 逻辑。
