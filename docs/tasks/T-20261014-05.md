一、问题（Hark 01:10 在 3da5410 上实测）
1. `Authorization: Basic dXNlcjpwYXNz` → `Authorization: [REDACTED] dXNlcjpwYXNz`。secretRE 只把方案名 "Basic" 当成值替换了，后面的 base64 凭据（user:pass）原样写进审计。这是 T-20261014-04 之前就有的问题。
2. 同类方案也有这个问题：Negotiate、NTLM、Token（例如 `Authorization: Token abc`）。Proxy-Authorization 也会被 secretRE 里的 authorization 命中，表现相同。

二、要求
1. 当 authorization（包括 Proxy-Authorization，不区分大小写，`:` 或 `=` 赋值）的值是 basic / negotiate / ntlm / token 之一，且后面跟着空白和凭据时：保留方案名原样，把凭据换成 [REDACTED]。凭据遇到空白、逗号、分号、单引号、双引号就结束。
   - `Authorization: Basic dXNlcjpwYXNz` → `Authorization: Basic [REDACTED]`
   - `-H "Authorization: Basic dXNlcjpwYXNz"` → `-H "Authorization: Basic [REDACTED]"`（右引号保留）
   - `Proxy-Authorization: basic abc` → `Proxy-Authorization: basic [REDACTED]`
   - `authorization=NTLM abc` → `authorization=NTLM [REDACTED]`
2. 结果里 [REDACTED] 恰好出现一次，原凭据不得出现。
3. 以下行为与 3da5410 逐字一致（回归）：
   - `Authorization: Bearer abc123` → `Authorization: Bearer [REDACTED]`
   - 单独出现的 `Bearer abc123` → `Bearer [REDACTED]`
   - `Authorization: abc123`（没有方案名）→ `Authorization: [REDACTED]`
   - `Authorization: Basic`（后面没有凭据）→ `Authorization: [REDACTED]`
   - `token=abc`、`api_key: abc`、`password=abc`、`cookie: a=b`、`bearer: abc` 的输出不变
   - 8192 字节 UTF-8 截断不变，Truncate 不变
4. 不做：Digest（参数形式，凭据是一次性摘要）；curl -u user:pass；`token=Bearer x` 会输出两个 [REDACTED] 的问题（不泄露）；不改调用方；不迁移历史审计行。
