## 一、问题

internal/executor/fs.go 的 Search 对遍历到的每个普通文件执行 os.ReadFile 读入完整内容，再按行查找。Hub 的 API 和 Agent 的 search 都调用它。在有大日志、大数据库文件或二进制文件的节点上，一次搜索会把几个 GB 的内容读进内存，并且二进制文件产生无意义的匹配结果。

## 二、要求

1. 新增常量 MaxSearchFileBytes = 10 * 1024 * 1024。大小超过该值的文件跳过，不读取。大小等于该值的文件正常搜索。
2. 新增二进制判断：文件前 8 KiB（8 * 1024 字节）中含有 NUL 字节（0x00）则视为二进制，跳过。前 8 KiB 之后出现的 NUL 不参与判断（这是有意的启发式规则，测试会固定这一行为）。
3. 单个文件读取失败、跳过的文件，都静默跳过，与修改前一致；不新增错误返回。
4. SearchResult 结构、返回排序、maxResults 上限、ctx 取消行为全部不变。
5. 符号链接仍然不跟随（修改前已跳过，保持不变）。

不做：
- 不改 Hub 或 Agent 的调用代码；
- 不改 search 的 JSON 字段；
- 不做流式逐行读取（另议）。
