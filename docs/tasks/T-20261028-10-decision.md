# 决策备忘：DevTask 模型 URL 与 API Key（OPC 已选方案 B）

## 已决定
- 管理员可以在管理面板中填写模型提供商的 API URL 与 API Key（方案 B）。
- 这需要修订现行规格：第 39 行“网关 key 不进 Hub 进程”、第 117 行“key 只在 runner 本机 runner.env”。修订须由 OPC 批准，并由 Hark 审核安全边界。

## 待 OPC 决定的子选项
1. key 如何到达模型调用方：
   - B1：runner 在领取任务时从 Hub 取得 URL 与 key，只驻留内存。前提：runner 与 Hub 同机且仅走 localhost，或先为 Hub 增加 TLS。当前 Hub 没有 TLS，生产为 http://192.168.20.132:9521，不能在明文局域网下发 key。
   - B2（建议）：Hub 代理模型调用。key 永远留在 Hub 进程内，runner 通过 Hub 发起模型请求，只拿到模型返回的内容。代价：每一轮模型调用都经过 Hub，并改变规格中“runner 直接调模型”的架构。
2. 加密主密钥：沿用通知密钥的模式，即 `VPS_COMMANDER_PROVIDER_KEY` 写入 /etc/vps-commander/hub.env（属主 root，600），32 字节，AES-256-GCM 加密数据库中的 key。主密钥不得放入仓库或数据库。部署与审计只报计数，不打印值（参照 T-20261014-23）。
3. 依赖顺序：D3–D6 与 DevTask B 先合并到 main，再派发实现卡。

## 不论选哪个子选项都必须满足
- 面板只显示掩码，修改时重新输入；留空表示不修改，不能无意清空。
- 任何接口响应、日志、审计详情、任务卡中都不出现 key 的值。
- 白名单外的模型、未配置 key 的提供商，不会被请求，也不会切换到其他提供商（沿用规格第 45、68 行）。
