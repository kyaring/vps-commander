一、背景（Hark 核对，dce83f0）
1. 节点离线的 episode 状态只放在内存里：notify.go 的 Manager.offline map[string]*offlineState{since, sent, notified}。check() 发现节点离线时调用 handleOffline 按 offlineSteps 分档提醒，节点恢复在线时如果 notified 就发 node_recovery。
2. Hub 重启后这份状态就没了，带来两个问题：
   a. 离线时长小于 offlineAlertLateStart（默认 120 分钟）的 episode 会从第 1 档重新判断，已经发过的提醒会再发一次；
   b. 离线超过 120 分钟的节点被直接视为全部已发（sent=len），notified 是 false，节点恢复时不会发 node_recovery；重启前已经提醒过的节点，恢复时也收不到通知。
3. 资源告警已经有现成的持久化方案可以照着做：storage/resource_alerts.go（resource_alert_states 表、migrateResourceAlertStates 在 storage.go:109 调用）+ notify.go 的 loadResourceAlertStates / persistResourceAlertState。原 bae08f2 用的表名是 notification_offline_states，沿用这个名字。

二、要求
1. 新文件 internal/storage/offline_states.go，结构照着 resource_alerts.go 写：
   - 表 notification_offline_states(device TEXT PRIMARY KEY, since INTEGER NOT NULL, sent INTEGER NOT NULL DEFAULT 0, notified INTEGER NOT NULL DEFAULT 0, updated_at INTEGER NOT NULL)，用 CREATE TABLE IF NOT EXISTS；
   - 方法 ListOfflineStates / SaveOfflineState（upsert）/ DeleteOfflineState；
   - storage.go 的迁移流程里加一行调用（紧跟在 migrateResourceAlertStates 后面），其他不动。
2. notify.go：
   a. NewManager 里像 loadResourceAlertStates 一样，加载离线状态到 m.offline；加载失败只记日志，不中断启动。
   b. handleOffline 里新建 episode（st 为空或 since 变了）时保存一次；sent/notified 变化时，先保存再 emit。
   c. 节点恢复在线时删除这一行；如果加载回来的状态里 notified=true，照常发 node_recovery（离线时长用持久化的 since 计算）。
   d. 重启后如果设备的 offline_at 跟持久化的 since 不一样，就当成新 episode（沿用现有 st.since != since 的判断）。
   e. 清理：check() 时，持久化状态里有、但 ListDevices 已经没有的设备（被删除或吊销），删掉那一行，不发通知。
   f. 保存或删除失败只记日志（日志里只写设备名和错误），行为跟现在的纯内存方式一样，不影响通知。
   g. 现有的 offlineAlertLateStart 规则保留：第一次见到、而且已经离线超过 2×最后一档的 episode，仍然不补发离线提醒（sent=len, notified=false）。
3. 测试（只新增文件）：
   - internal/storage/offline_states_test.go：表能建出来；Save 是 upsert；List 和 Delete 正常。
   - internal/notify/offline_persist_test.go（参考 notify_test.go 的 offlineFixture 和 setDevice）：
     ① 离线 1 分钟、发出第 1 档后，用同一个 store 新建一个 Manager 模拟重启，时钟仍在第 1 档和第 2 档之间：不再发离线提醒；推进到第 2 档：只发第 2 档。
     ② 发过提醒后重启，然后节点恢复：会发 node_recovery，而且这一行已经删掉。
     ③ 重启后 offline_at 变了：按新 episode 从第 1 档开始。
     ④ 设备从 devices 表删掉后，check 一次，这一行被清理，没有发任何通知。
     ⑤ 没发过提醒（离线超过 late start）的节点恢复时，不发 node_recovery（行为跟现在一样）。
