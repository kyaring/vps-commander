## 一、背景（审核结论）

审核已确认存在三处规格与实现/事实不符，需要文档修订：

1. **规格第 1 节自相矛盾（阻塞项）**
   - `docs/recovery/salvage/devtask/devtask-v1.1.36-taskbook.txt:55` 写：`devtask:run`：只给 runner 自己的命名 token。
   - 同文件 `:58` 写：admin 隐含全部 devtask scope，但 admin token 仍不能在 OAuth consent 中被选用。
   - 代码实现取的是前者：`internal/auth/auth.go:44-46` 有显式特判与注释「devtask:run is never implied by panel, system, or admin」，并有单测 `internal/auth/auth_devtask_test.go` 锁定。

2. **规格修订 1028 的安全边界尚未复核，且缺少残留风险明示**

   - **OPC 裁定：接受该方案**，但必须在文档中明示三项硬性前提与一项残留风险（见第二节第 2 条）。

3. **空白名单语义未写明**
   - 实现为 fail-closed：`internal/storage/devtask.go:179-199` 的 `GetDevTaskAllowedModels` 在设置缺失时返回空列表，`internal/api/devtask.go:91-95` 对不在列表中的模型一律 400 拒绝。

## 二、要求

1. **修订 `docs/recovery/salvage/devtask/devtask-v1.1.36-taskbook.txt` 第 58 行**
   - 原文：`admin 隐含全部 devtask scope，但 admin token 仍不能在 OAuth consent 中被选用（沿用 v1.1.31 规则）`

2. **修订 `docs/devtask-spec-amendment-1028.md`，补「复核结论」一节**
   - 把文件头第 5 行「本修订需要由 Hark 复核安全边界」改为「本修订的安全边界已于 2026-11-11 由 OPC 复核并接受」。
   - 新增一节「复核结论与硬性前提」，写明：
     - **前提 1**：取凭据接口必须同时校验四项——`lease_id` 有效且未过期、模型在白名单内、provider 已启用、调用方为 runner 命名令牌；四项全满足才下发，任一不满足即拒绝。
     - **前提 2**：审计只记录 `provider_id`、`model`、`lease_id`、结果，**绝不记录 key 值**（含截断、哈希、前缀）。
     - **前提 3**：`X-Forwarded-Proto` 仅作辅助防护，不得作为唯一来源判定；局域网客户端可伪造。
     - **残留风险（必须明示）**：key 会经过 Cloudflare 边缘（对外入口 `https://vcs.king.nyc.mn`），Cloudflare 到源站的链路无法从本机核实；主密钥丢失则已存 key 无法解密，需重新填写。
