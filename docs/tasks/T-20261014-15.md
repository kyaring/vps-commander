一、背景（Hark 核对，3610a7b）
1. OPC 05:46 在面板新建 wecom_bot 通道 wecom-system 时，面板提示「保存通道失败：channel config must be a JSON object」。
2. 原因：internal/web/static/app.js 第 734 行 saveNotificationChannel 的 payload 写的是 config_json:JSON.stringify(config)，请求体里的 config_json 因此是一个 JSON 字符串，例如 "{}"。
   API 端 notificationChannelInput.ConfigJSON 的类型是 json.RawMessage（internal/api/notifications_v1.go:16），拿到的就是这个字符串字面量。
   SaveNotificationChannel 解析后得到的是 string，不是对象，于是在 internal/storage/notification_store.go:96 返回这个错误。
   结论：面板新建或编辑任何类型的通道都会失败。API 直接传对象是正常的。
3. 同一行附近的 variables_json、event_types_json、severities_json、policy_json 在 API 端都是 string 字段，二次序列化正好对，本卡不动。
