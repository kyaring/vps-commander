## 一、背景
1. 方案 C 已让「单次回传」与「会话预算」可见（T-20261014-21 / T-20261014-28），但**重复劳动**仍在：调用方每轮重新推导同一批事实（实测一个会话里同类状态查询跑了 6 轮）。
2. 目标：给调用方一个**会话级便签**，把「我核对过什么、结论是什么、对应哪个 sha」写进去，后续直接读回，不再重复核验。
3. 设计依据：`docs/design/CONTEXT-BUDGET.md` §二 原则「聚合在服务端」「默认窄、按需宽」。

## 二、要求
1. 新增**会话级键值便签**，会话身份口径**与 T-20261014-28 的 session_stats 一致**（MCP 会话 id；非 MCP 按「令牌 + remoteAddr」归并）。**只存内存、Hub 重启清零、不写数据库。**
2. HTTP 接口（canonical）：
   - `POST /api/v1/session/memo`，body `{"key":"...","value":"...","ttl_seconds":<可选>}` → 写入/覆盖，返回 `{"key":...,"bytes":N,"expires_at":<可选>}`
   - `GET /api/v1/session/memo?key=...` → `{"key":...,"value":...,"bytes":N,"updated_at":...}`；不存在返回 **404**
   - `GET /api/v1/session/memo` → **只列元数据**（`key`、`bytes`、`updated_at`，最多 32 条），**不返回 value**
   授权：任何有效令牌；**只能读写自己的会话**，不得读他人；不新增 scope。
3. MCP 工具 `memo_set` 与 `memo_get` 加入 `tools/list`（薄封装，字段与上面一致）；`memo_get` 不传 key 时返回元数据列表（等价于 HTTP 的 list）。
4. 配额（防止便签变成新的膨胀源）：单个 value **≤4KB**；每会话 **≤32 条**；每会话总量 **≤32KB**。超限返回 **413** 并给出明确错误（含当前用量与上限）。
5. **保密要求**：审计与日志**只记 key 与字节数，绝不记 value**；给了 `ttl_seconds` 的条目到期后自动失效（惰性清理即可）。
6. `docs/api.md` 补接口说明与示例；`docs/client-skill/SKILL.md` 补一段推荐用法（「把已核对的结论与 sha 写进便签，避免重复查询」）。
7. 新测试只放新文件 `internal/api/session_memo_test.go`，**不得修改现有测试文件**。至少覆盖：
   - 写入 / 读回 / 覆盖；
   - 不存在的 key 返回 404；
   - list **只返回元数据、不含 value**；
   - **两个令牌互不可见**；
   - 三条配额上限各自触发 413；
   - TTL 到期后读不到；
   - 审计与日志**不含 value**（只含 key 与字节数）。
8. 反向验证：把 list 的「只返回元数据」改成返回 value，要求 7 中对应用例必须失败。
9. 不做：不做持久化、不做跨会话共享、不做面板、不改审计既有字段、不新增 scope、**不改 `internal/api/session_stats.go`**（T-28 的实现本卡不动）。
