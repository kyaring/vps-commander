一、目标
1. 新增四个 scope：devtask:submit、devtask:read、devtask:cancel、devtask:run。它们不加进 legacy key 的固定 scope 集合（internal/auth/auth.go 中 legacy 与 env bootstrap 的 Scopes 不变）。
2. 令牌创建接口（internal/api/tokens.go 中两处 allowed 白名单）接受这四个 scope。
3. admin 隐含全部 devtask:* scope：Principal.HasScope("devtask:x") 对拥有 admin 的主体返回 true；其他 scope 的行为不变。
4. OAuth：
   - devtask:submit、devtask:read、devtask:cancel 可被授予；
   - devtask:run 显式拒绝：请求中出现即返回 invalid_scope，不做静默忽略；
   - 未指定 scope 时的默认授予集合不包含任何 devtask:* scope；
   - admin 令牌仍不能在 consent 中被选用（沿用现有规则，本卡不改它）。
5. admin 专用接口（requireScope("admin")）：
   - GET /api/v1/devtask-projects：列出项目；每项附 model_ok（default_model 是否仍在白名单内）；
   - POST /api/v1/devtask-projects：新增或修改项目（upsert）。default_model 必须在白名单内，否则 400；repo_path 必须是绝对路径；max_rounds、max_steps、timeout_s 必须 >= 1；修改时写审计（旧值、新值、操作人）；
   - GET /api/v1/devtask-settings：返回 allowed_models（白名单）与 enabled（开关状态）；
   - PUT /api/v1/devtask-settings：整体替换白名单。调用 storage.SetDevTaskAllowedModels；写审计，内容含旧白名单、新白名单、操作人；空名与重复名返回 400。
6. 开关：所有本卡新增的接口在 DEVTASK_ENABLED 未设置或不是 on/true/1（不区分大小写）时返回 404。开关只在 internal/api 中读取环境变量，不改 cmd/hub。
7. 审计：项目与白名单的每次修改都写 audit_logs，带 actor_name 与 oauth_client_id（沿用 auditContext）。
