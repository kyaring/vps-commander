对照 Armin《What is Codemode》和 Cloudflare 的 search/execute 设计复盘 Hub MCP。结论是工具定义不动（14 个约 5.7KB），要改的是返回层和会话层。本卡对 `tools/list` **零字节改动**：不加参数、不改描述、不加 outputSchema 或 annotations，这些都留给 T-20261016-03。

## 必改
A. **溢出文件**：exec 输出被截断（超过 max_bytes，或 head/tail/count/none 模式丢弃了内容）时，把**完整**的 stdout 和 stderr 写到执行命令的那台节点上一个固定目录里的溢出文件（文件名用 sha256，权限 0600，TTL 24 小时，过期由后台或下次写入时清理；目录总量设上限，超了先删最旧的）。返回中增加 `spill_path`。必须能用现有的 `read_file`（同一个 device、offset/limit）分页读到该文件；如果 read_file 有路径白名单，要把溢出目录纳入。没被截断时不写文件，`spill_path` 为空串。
B. **返回形状收敛**：`execOutputResponse`（api.go 约 1772 行）及 MCP 的 exec 结果，在所有 output_mode 下都返回同一组字段：`exit_code`、`stdout`、`stderr`、`truncated`、`total_bytes`、`total_lines`、`sha256`、`spill_path`，字段始终存在；count 和 none 模式只把 stdout 置空串。同时以 structuredContent 返回同一个对象；text 内容保持现有格式（兼容旧客户端）。
C. **预算按令牌计算**：把 `sessionBudgetKey` 拆成两个函数：
   - 预算和 `/session/stats` 使用新的按令牌 key，用 `sessionBudgetRecord` 里已有的 ownerTokenID 聚合，窗口为滑动 24 小时；
   - memo 继续使用原来的会话 key，函数改名（例如 `sessionMemoKey`），行为不变。
   预算**仍然只告警**、不阻断，阈值仍为 2 MiB，不新增配置项。`/session/stats` 的语义同步改为按令牌统计，并在 docs/api.md 写明。
D. **未知会话优雅降级**：带了未知或过期 `Mcp-Session-Id` 的请求（mcp.go 约 898 和 1021 两处 404），改为当成新会话处理：建立新会话，在响应头返回新的 `Mcp-Session-Id`，请求照常执行。鉴权不变：Bearer 令牌无效照样 401。必须在 C 完成后做（否则换 id 就能把预算清零）。
E. **tools/list 回归测试**：固定 `tools/list` 响应 JSON 的 sha256 和字节数，并断言字节数 ≤ 10240；失败时打印新旧哈希和字节数。本卡交付时哈希必须与 main 一致（证明零字节改动）。
F. **文档**：docs/api.md 补充 spill_path 和统一的返回字段；docs/client-skill/SKILL.md 说明截断后怎么用 read_file 读溢出文件，以及 dedup_window_seconds 只在「同一轮核验里重复跑同一条命令，且确认中间没有写操作」时才用（dedup 默认值保持 0，不得改动）。

## 测试
1. 大输出（> max_bytes）：truncated=true，spill_path 非空，文件内容的 sha256 等于返回的 sha256，用 read_file 读中段的偏移得到正确字节。
2. 小输出：spill_path 为空串，不产生文件。
3. 五种 output_mode 的返回字段集合完全一致（表驱动）。
4. 溢出文件权限为 0600；TTL 过期后被清理；总量超上限时最旧的被删除。
5. 同一个令牌用两个不同的 MCP 会话 id 调用，预算累计到同一个桶；不同令牌互不影响。
6. 用未知会话 id 调用：返回 200，响应头带新的会话 id，结果正确；用无效令牌仍然 401。
7. memo 回归：T-30 的 memo 测试原样通过，memo 仍按会话隔离。
8. tools/list 的哈希和字节数断言（E）。

## Errata 1（Hark，2026-10-16 06:58，回应 RikkaHub-1 开工前的问询）
1. **C 采用聚合式（方案 i）**：`sessionBudgets` 的存储 key 仍是会话，memo 的过期和归属路径一行不改。卡面里「新的按令牌 key」改为：新增一个按 `ownerTokenID` 汇总的**查询函数**。预算告警和 `/session/stats` 都改用它，汇总范围是该令牌所有尚未过 idle TTL（24h）的会话记录。2 MiB、仅告警、不阻断，都保持不变。不需要做逐字节时间戳的滑动窗口，「24h 窗口」即上面说的 idle TTL 语义。测试 5 按此验收：同一令牌的两个会话累计到同一个汇总；不同令牌之间互不影响；会话过期后它的字节不再计入。
2. **D**：`TestHandleMessageRejectsUnknownSessionID` 断言的正是 D 要删除的行为，属于预期内的改动，允许改断言。但必须另外新增或保留一条安全断言：**会话 id 已存在、但属于其他令牌时，仍然拒绝，绝不降级、绝不复用**。降级只适用于完全未知（或已过期）的 id，新会话归当前令牌所有。改动前后的断言要在交付消息里对照写明。
3. **A 白名单**：`read_file` 没有路径白名单（`validPath` 只检查 NUL 和前导 `-`），所以「纳入白名单」这一条作废，交付时记为「无白名单、无需改动」。溢出文件的文件名必须是随机的，放在专用目录下，权限 0600。
4. **A 远端写入**：允许在 `internal/api/` 里调用现成的 `Cluster.WriteFile`，`internal/cluster/` 仍然禁止修改。如果现有接口没法保证 0600（没有 mode 参数，或者远端的 umask 让结果不可控），立即停下来报 Hark，不得绕开限制，也不得修改 cluster。
