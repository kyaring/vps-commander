## 审核补充说明（9398e61 后续修订）

### outputSchema 豁免理由与真实成功返回结构

以下四个文件写入工具执行成功后返回的是简短操作确认对象，而不是需要下游消费的结构化数据集合；当前 MCP 响应层对它们仅生成文本 `content`，不生成 `structuredContent`，因此不声明 `outputSchema`。这不是因为返回结构未知，而是因为它们属于简单写操作确认，且当前协议层明确不发布 structured output。

| 工具 | 成功返回结构（字段及类型） | 豁免理由 |
|---|---|---|
| `create_directory` | `{"device": string, "path": string, "ok": boolean}` | 仅确认目标目录创建成功；无后续结构化数据消费需求 |
| `move_file` | `{"device": string, "source": string, "destination": string, "ok": boolean}` | 仅确认源路径移动到目标路径；无后续结构化数据消费需求 |
| `edit_block` | `{"device": string, "path": string, "bytes_written": integer}` | 仅报告一次原子文本块替换及写入字节数 |
| `write_file` | `model.FileWriteResponse`：`{"device": string, "path": string, "bytes": integer}` | 仅报告一次文件写入及写入字节数 |

`memo_set` / `memo_get` 也继续保留为兼容工具，不声明 `outputSchema`；二者已废弃，描述明确引导使用 scratch 文件和 `read_file`。测试 `TestDeprecatedMemoAndSimpleWriteToolsRemainOutputSchemaExempt` 固定了这些豁免，且断言这些工具不产生 `structuredContent`。
