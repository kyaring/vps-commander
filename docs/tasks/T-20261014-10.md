一、背景（Hark 核对，e9cbcfb）
1. 内置模板只有 development-completed 和 review-completed 两种回报（storage/notification_v1.go:240-241），只能报「完成」，看不出是谁、哪个项目，也报不了「受阻」。
2. OPC 规定：下发的任务可以有多种类型（开发、测试、运维、巡检、审核等），员工交回任务时，不管是做完了还是受阻，都必须推送通知，让 OPC 第一时间知道状态。
3. 工号规则（OPC 04:01）：SWS-<类型字母><三位数字>-<名字>，例如 SWS-E001-hark。员工表放到后面的卡里做，本卡先用调用令牌的 Name 作为员工标识的缺省值。
4. development-completed 和 review-completed 保留不动，旧脚本和生产流程继续可用，所以本卡不需要做模板迁移。

二、要求
1. 新增内置模板（写法同 builtin-default，INSERT OR IGNORE，已经存在就不覆盖）：
   - ID task-reported，Name「任务回报」，EventType task.reported，Severity P3，Format text
   - 变量 ["employee","project","task","type","status","ref","summary"]
   - 标题「【{{employee}}】{{type}}{{status}}：{{project}}」
   - 正文「任务：{{task}}\n关联：{{ref}}\n摘要：{{summary}}」
2. POST /api/v1/events 在 template_id=task-reported 时：
   a. status 必填，只接受 done、blocked、failed，存入和渲染前分别换成「完成」「受阻」「失败」；其他值返回 400；
   b. severity 没传时：done 用 P3，blocked 和 failed 用 P2；传了就以传入为准；
   c. employee 为空 → 用调用令牌的 Name，Name 也为空就用 source；project 为空 → 填「-」；ref 为空 → 填「-」；type 为空 → 填「任务」；
   d. task、summary 必填；
   e. employee、project、type、ref：去掉首尾空白后，employee 和 project 最多 32 个 rune，type 最多 16 个，ref 最多 64 个；不能含控制字符，也不能含「【」「】」，否则返回 400（复用 rejectNotificationEvent）；
   f. 幂等哈希按客户端原始请求（填充前）计算，同一 Idempotency-Key 重放结果不变；data_json 存填充和转换之后的变量；
   g. 只对 task-reported 生效，其他模板的行为一律不变。
3. scripts/notify-agent-completion.sh 新增 task-reported 模式：
   task-reported --task-id ID --type TYPE --status done|blocked|failed --summary TEXT [--employee ID] [--project NAME] [--ref TEXT]
   - --employee 没传就取环境变量 VPS_COMMANDER_EMPLOYEE，--project 没传就取 VPS_COMMANDER_PROJECT；都没有就不放进 variables，交给 Hub 填；
   - 本地做和 Hub 相同的校验，不合格就 exit 2；Idempotency-Key 用 task:<task>:<status>:<ref 或 summary 的短哈希>；
   - development-completed 和 review-completed 两种模式的行为不变；
   - scripts/test_notify_agent_completion.sh 补上相应用例。
4. 文档：
   - docs/client-skill/SKILL.md、docs/mcp-clients.md、docs/process/PROJECT-PROFILE.md 写明：交回任务时必须推送 task-reported，做完推 done，受阻推 blocked 并在摘要里写清阻塞原因和需要谁来处理；各给一条完整示例（工号写成 SWS-E002-gpt 这种格式）；
   - docs/api.md 补上本模板的变量、填充、校验、severity 规则；
   - 客户端 skill 有版本号的话，加 0.1。
   不做：不建员工表、不改通知渠道和路由、不做兜底通道（另开卡）、不改历史事件、不改 emit-notification-event.py。

三、测试（新测试只放在新文件里，脚本测试除外）
