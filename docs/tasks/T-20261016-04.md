## 1. 背景
无需认证的 /probe/summary 在生产上返回 200，内容含节点名、国家、节点网络累计流量、开机时间、docker 标记（10-16 只读实测）。
证据：internal/web/panel.go:80 注册为 cachedHandler("probe-summary", p.probeSummary)；panel.go:378-384 的 probeSummary 直接调用 p.Runner.DevicesJSON；internal/api/api.go:599 的 DevicesJSON 转发给 devices()；api.go:1038 起的 devices() 输出完整的 model.Device，包括 name、country、remote_ip 和全部 profile 字段（字段见 internal/model 的 Device 与 internal/sysinfo 的 Profile）。
OPC 10-16 选 A：保留公开，但只返回不能识别节点身份的最小摘要。

## 2. 要求
1. probeSummary 先取 DevicesJSON 的结果，再经白名单投影后输出；投影只在新文件 internal/web/probe_summary.go 中实现，不改 internal/api 的任何代码。
2. 每个元素只保留键 status、arch、os；profile 只保留 cpu_usage_percent、mem_percent、disk_percent。其余键一律丢弃（白名单，不是黑名单）。
3. 输出中不得出现：name、is_local、remote_ip、country_code、country、profile.role、cpu_cores、load_1m、load_5m、load_15m、net_rx_rate、net_tx_rate、net_rx_total、net_tx_total、uptime_seconds、boot_time、mem_available、disk_free、io_psi、docker、updated_at。
4. 输出为 JSON 数组；上游无设备时输出 []；元素顺序保持上游顺序。
5. cachedHandler、2 秒缓存、ETag、非 GET 返回 405 的行为保持不变。
6. 上游 DevicesJSON 返回非 200 时，原样透传状态码和响应体，不做投影。
7. /api/v1/devices 与 /panel/api/devices 的返回不变，仍是完整字段。
8. docs/api.md 第 125 行改为说明只返回 status、arch、os 与三项资源百分比；docs/security.md 增加一小段，说明 /probe/summary 的暴露范围。
不做：不改节点名称的存储或展示；不加认证；不改 static 下的页面文件。若发现页面依赖被删除的字段，停下报告，不要改页面。
