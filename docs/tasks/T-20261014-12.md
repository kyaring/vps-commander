一、背景（Hark 核对，生产 48505f6）
1. 旧版 webhook 存在 webhook_targets 里，url 是明文。Hub 每次启动时，notification_v1.go 的迁移都会用 INSERT OR IGNORE 根据它建出 legacy-webhook:<id> 通道和 legacy-task:<id> 任务，通道的 endpoint 也是明文。
2. 现有 API 删不掉旧通道：DisableNotificationChannel 会跳过 legacy 通道；Save/DisableNotificationTask 遇到 legacy-task: 直接报错；webhook/update 和 webhook/delete 已经返回 410（T-08）。
3. 生产里有两条旧 webhook：wecom-dev、wecom-review，类型都是 wecom。dev-completed-wecom、review-completed-wecom 两个任务也挂在旧通道上。notification_deliveries 里有 32 条历史投递引用旧通道，外键是 RESTRICT，所以旧通道和 legacy-task 的行不能物理删除。
4. OPC 要求去掉所有旧版 webhook，而且迁移过程中任何人都不能看到地址。

二、要求
1. 新增 admin 接口 POST /api/v1/notifications/legacy/retire（requireScope admin），请求体：
   {"legacy_webhook_id":"wecom-dev","channel_id":"wecom-dev-bot","name":"企业微信-开发群"}
   三个字段都必填。channel_id 用现有通道 ID 的校验规则，不能以 legacy- 开头。
2. 在一个事务里完成以下步骤，任何一步失败就整体回滚：
   a. 从 webhook_targets 读出该行。不存在时：如果 channel_id 已经是本操作建的 wecom_bot 通道，返回 200 并带 already_retired:true（幂等）；否则返回 404。
   b. 校验 url 是企业微信机器人地址，规则同 notification_store.go:62，复用或照抄成新文件里的私有函数，不改原文件。不合格就返回 400，错误信息里不能带 url。
   c. channel_id 已存在且不是 a 中的幂等情况 → 409。
   d. 新建 wecom_bot 通道：secrets 为 {"webhook_url":<原 url>}，加密方式和 SaveNotificationChannel 一样（调用它或它的加密函数，不要另写一套）；config 为 {"mentioned_list":[]}；enabled 沿用旧行的值。
   e. UPDATE notification_tasks SET channel_id=<新通道> WHERE channel_id=<旧通道> AND id NOT LIKE 'legacy-task:%'。
   f. legacy-task:<id> 置 enabled=0。旧通道置 enabled=0、endpoint=''，name 后面加「（已退役）」，config_json 清成 '{}'。这两行保留，留给历史投递引用。
   g. 该 legacy 任务下还在 pending 或待重试的投递，改成现有的失败终态，last_error='legacy webhook retired'，以后不再投递。
   h. DELETE webhook_targets 和 webhook_delivery_state 中该 id 的行。这样下次启动时迁移不会再建出旧通道和旧任务，明文 url 也就从库里消失了。
   i. 响应只返回 {"ok":true,"channel_id":..,"moved_tasks":[..],"retired_task":..,"already_retired":bool}，不带 url 和 secrets。
3. GET /api/v1/notifications/webhooks（WebhookTargetsJSON）不再返回明文 url，改成只返回 scheme 加 host 再加「/…」，例如 https://qyapi.weixin.qq.com/…。另外请核查 GET /api/v1/notifications/channels 会不会返回 legacy 通道的明文 endpoint：如果会，就停下来报告，不要改 notification_store.go。
4. 文档：docs/api.md 写清新接口、幂等行为、各种错误码，以及「旧通道和旧任务保留成停用行」；docs/process/PROJECT-PROFILE.md 加一行说明旧版 webhook 已通过 retire 接口退役。
   不做：不建系统群通道，不配新路由，不做兜底通道，不改面板，不改 MCP，不清理历史投递里的 rendered_message。
