背景：2026-10-28 的切换事故源于“先停服务、后备份”和临时脚本缺少回滚约束。
要求：
1. --dry-run 只打印将要执行的每一步，不改动任何文件，不停服务。
2. 顺序强制：备份（二进制 cp、数据库 sqlite3 .backup）成功并校验非空之后，才允许停服务。备份失败立即中止，服务不被触碰。
3. 替换采用临时文件加 mv 原子替换；替换后启动，健康检查要求返回 {"status":"ok"}。
4. 健康检查失败时只回滚二进制，并输出 ROLLBACK OK 或 ROLLBACK FAILED；数据库不自动回滚，只提示人工步骤。
5. 脚本拒绝在存在活动的 deploy 进程锁时运行（使用 flock）。

测试（deploy/test-deploy-hub-local.sh，在 mktemp 目录中用假的 systemctl 与假的 Hub）：
- 备份失败时服务不被停止；
- 健康检查失败时二进制被回滚，数据库未被改动；
- --dry-run 不产生任何文件变化；
- 并发运行时第二个实例拒绝执行。
