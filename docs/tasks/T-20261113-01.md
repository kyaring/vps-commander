### 第二部分：连通性测试（后端 + 前端）

**新增接口**：`POST /api/v1/devtask-providers/{id}/test`，admin scope，受 `devtaskGate` 约束。

行为：
1. 读取该 provider 的 `base_url` 与解密后的 `api_key`；
2. 向 `base_url` 发一个**最小**的模型可用性探测请求（见下方「探测方式」）；
3. 返回结构化结果：
   ```json
   {"ok":true,"status_code":200,"latency_ms":123}
   ```
   或
   ```json
   {"ok":false,"status_code":401,"error":"unauthorized"}
   ```
4. **超时 10 秒**，超时返回 `{"ok":false,"error":"timeout"}`。

**探测方式**（务必按此实现，避免误判）：
- 方法：`GET`
- 路径：`{base_url}/models`（OpenAI 兼容约定的模型列表端点）
- 请求头：`Authorization: Bearer <api_key>`
- 判定：
  - HTTP `2xx` → `ok=true`
  - HTTP `401` / `403` → `ok=false`，`error` 为 `unauthorized` / `forbidden`
  - 其他 4xx/5xx → `ok=false`，`error` 为 `http_<status>`
  - 网络错误 → `ok=false`，`error` 为 `network_error`
- **不得**把响应体内容返回给前端（可能含敏感信息），只返回状态码与错误类别。

**审计**：写一条审计 `action=devtask_provider_test`，`target=<provider_id>`，`command` 只写 `base_url=<host>`（**只写 host，不写完整 URL 的 query/path**），结果记 `ok` / `error`。**绝不记录 api_key**。

**前端**：列表每行加「测试」按钮，点击后调用该接口，把结果以文字显示在按钮旁（如「✓ 200 (123ms)」/「✗ unauthorized」）。测试期间按钮禁用并显示「测试中…」。
