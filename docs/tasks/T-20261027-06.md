## 背景
T-20261016-02 只交付了 Hub 本机异步（OPC 10-27 17:42 接受）。远端 agent 的 exec 用的是 context.Background() 加自身超时，协议里没有取消 exec 的消息，所以 Hub 取消后远端进程会继续跑。不过现有 agent 已经具备 start_process、read_process_output、kill_process、list_sessions 这几项能力（见 hello capabilities）。本卡在不改 agent 的前提下，用会话进程实现可以真正取消的远端异步。

## 必改
A. exec_start 对远端设备：经由会话进程启动命令，job 记录 session/pid；exec_status 的状态集合、字段、溢出文件、24 小时保留、TokenID 归属、名额、审计，全部与本机 job 一致（复用 T-02 的实现）。
B. exec_cancel 对远端设备：调用 kill_process 或 force_terminate，确认进程已结束后再记 killed/cancel；kill 失败要如实返回，不得假装成功。
C. 最长运行时间：远端同样 60 分钟（由 Hub 计时，到时 kill）。如果 agent 的会话进程本身有上限，以实测为准，写进文档。
D. 名额：远端 job 占用名额，直到确认远端进程已结束（或 Hub 判定 lost）才释放。
E. 节点离线或 Hub 重启：远端 job 标 lost（reason 写 node_offline 或 hub_restart），名额释放；不能一直停在 running。
F. 改正 T-02 文档里「agent 持有节点的操作锁」这一错误说法，写出真实原因，并说明远端现在的做法。
G. tools/list：如果工具描述有改动，更新哈希，交付说明写明新旧哈希和字节数（≤ 10240）。

## 测试（用假 cluster 或假 agent，不连真实节点）
1. 远端 start → running → exited，退出码和输出正确。
2. 远端 cancel：确认 kill 已下发，状态变为 killed；kill 失败时返回错误，状态不变成 killed。
3. 远端 job 占用名额，cancel 后要等到确认进程结束才释放。
4. 节点离线时，job 变为 lost，名额释放。
5. 其他令牌查询或取消，与 job 不存在时返回同一个错误。
