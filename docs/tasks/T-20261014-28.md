## 一、背景
1. 方案 C 的 T-20261014-21 已把「**单次**回传」压到 ≤4KB，但**会话级**消耗仍不可见：调用方不知道自己在一次会话里已经回传了多少、哪些工具最贵，因此无法自我收敛。实测一个会话里同类状态查询重复了 6 轮。
2. 目标：让调用方**随时能看到自己的会话预算**，并在超阈值时**被主动提醒**。
3. 设计依据：`docs/design/CONTEXT-BUDGET.md`（§一 指标、§二 原则「默认窄、按需宽」「截断必须可见」）。

## 二、要求
1. 新增**只读**接口 `GET /api/v1/session/stats`。授权：任何有效令牌；**只统计调用方自己的会话**，不得暴露他人数据；**不新增 scope**。响应：
   ```json
   {"session_id":"<string>","started_at":"<RFC3339>","tool_calls":N,"bytes_returned":N,"est_tokens":N,
    "top_tools":[{"name":"exec_command","calls":N,"bytes":N}],
    "budget":{"limit_bytes":N,"used_pct":N,"warn":false}}
   ```
   - `est_tokens` = `bytes_returned / 4` 取整；字段含义写进 `docs/api.md`，并注明这是**粗估**、不是精确 tokenizer。
   - `top_tools` 最多 5 条，按 `bytes` 降序。
   - 响应体 ≤1.5KB；`session_id` **不得包含令牌或任何凭据片段**。
2. 统计口径：**当前调用方会话**自会话开始以来的「工具调用次数」与「回传给调用方的响应字节」。MCP（streamable HTTP）会话用其 session id；非 MCP 的 HTTP 调用按「令牌 + 最近一次连接起点」归并。**只存内存，Hub 重启即清零；不写数据库。**
3. 阈值与主动提醒：阈值取 `VPS_COMMANDER_SESSION_BUDGET_BYTES`（默认 `2097152` = 2MB）。当某会话累计回传字节**超过**阈值时，Hub 在该会话**后续每一次工具响应**里附加一个字段 `budget_warning`，例如：
   `"session budget exceeded: 2.4MB / 2.0MB; consider narrower queries (output_mode=count, dedup_window_seconds)"`。
   **不得改动任何现有响应字段与语义**（只是新增字段）；**未超阈值时不得出现该字段**。
4. `docs/api.md` 补该接口与 `budget_warning` 的说明与示例。
5. 新测试只放新文件 `internal/api/session_stats_test.go`，**不得修改现有测试文件**。至少覆盖：
   - 调用次数与字节统计正确（含按工具聚合、`top_tools` 降序取前 5）；
   - **只统计调用方自己**：用两个不同令牌构造，互不可见；
   - `est_tokens` 与 `used_pct` 计算正确；
   - 超阈值后响应里出现 `budget_warning`；**未超阈值时不出现**；
   - 响应体 ≤1.5KB，且 `session_id` 不含凭据片段。
6. 反向验证：把「超阈值才附加 `budget_warning`」的判定反转（或恒真），要求 5 中「未超时不出现」的用例必须失败。
7. 不做：不做持久化 / 跨会话聚合 / 面板展示；不改审计；不新增 scope；**不改 executor 的输出整形**（T-21 已完成）；不改 `hub.healthz` 与 `health/assertions` 接口。
