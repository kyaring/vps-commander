## 对照卡与 Errata
- A：溢出文件落在 Hub 本机数据库目录下的 mcp-spill/，目录 0700，文件用 O_EXCL 创建、权限 0600，文件名取 128 bit 随机数；TTL 24h，总量上限 256 MiB，超出时按最旧淘汰；单条输出超过上限时不落盘，只返回结果。属主映射只存在内存里，启动时清空目录。读取要求精确匹配记录、父目录等于 spill 目录、Lstat 为普通文件：符号链接、`..`、他人文件、过期文件、不存在的文件，一律返回同一个错误。
- B：所有模式返回同一组 11 个字段（加上 device、duration_ms、spill_device）；count 和 none 模式下 stdout、stderr 为空串；exec 成功时附带 structuredContent，text 内容保持不变；dedup 命中时也是同一组字段。
- C：按 Errata 1 采用聚合式方案，存储 key 仍按会话；预算告警和 /session/stats 汇总该令牌所有未过期的会话；memo 的 key 只是改了名，行为不变。
- D：未知或过期的会话 id 会新建会话，并在响应头返回新 id；会话存在但属于其他令牌时仍然 403；无效令牌仍然 401。新建会话复用原有的 500 个总数上限和每令牌上限（抽成了 openStreamSession）。
- E、F：哈希测试已到位；docs/api.md 与 SKILL.md 已同步；dedup 默认值仍是 0。

## 非阻塞事项
1. 溢出文件的属主用的是 `p.QuotaID()`，不是 Errata 2 写的 ownerTokenID。目前生产代码里没有任何地方设置 QuotaTokenID，所以两者等价；但将来如果启用共享配额，同一配额下的令牌就能互相读取溢出文件。后续卡要么改成 TokenID，要么在启用 QuotaTokenID 时一并评估。
2. OAuth 刷新令牌后 TokenID 会变：旧的溢出文件读不到，预算也重新计数。这和「按令牌」的语义一致，可以接受，建议在 SKILL.md 里补一句。
3. 写溢出文件时一直持有全局锁，包括 fsync（最多约 2 MiB），并发截断时会串行。目前量很小，可以接受。
4. REST 路径 /api/v1/file/read 读取 @hub-spill 时不写审计；MCP 路径写审计。建议后续补上。
5. DELETE 一个未知会话从 404 改为 204，超出了卡面范围，但幂等、有文档，予以接受。
