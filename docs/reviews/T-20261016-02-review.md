## 必改项
1. **（P2）远端 job 取消不会结束远端进程，还会绕过名额限制。** cmd/agent/main.go 处理 exec 时用的是 context.WithTimeout(context.Background(), timeout)，与 Hub 的请求无关；Hub 的 ctx 取消后，manager.call 只是在 ctx.Done 时放弃等待。结果：
   - exec_cancel 对远端 job 返回 killed/cancel，文档还写着「结束整个进程组」，但远端进程会继续跑，直到 agent 的 300 秒上限；
   - runJob 返回后立刻 release 名额，同一令牌可以反复 start 再 cancel，在远端堆起任意多个进程（每个最多 300 秒），名额限制被绕过。
   修法（不改 cmd/）：远端 job 被取消后，名额一直占到「start 时间 + remoteMax」才释放（或等到 agent 真正返回为止，取二者中较早者以外的安全值）；状态写 killed，reason 写 **cancel_remote_pending**（或另写一个字段），明确表示远端进程最多还会运行到 300 秒上限；docs/api.md、SKILL.md 和 exec_cancel 的工具描述要写清这一点（工具描述改了，tools/list 哈希要同步更新）。补测试：用假 cluster 模拟远端 job，cancel 之后名额不会立刻释放，到期才释放。
2. **（P3）输出实际保留时间超过 24 小时。** job 记录 JSON（含 Shaped 预览，最多 4KB 的 stdout/stderr，以及命令摘要）要等 7 天（jobForgetAfter）才删；get 只是在返回的视图里把它隐藏掉。卡 D 要求「结束后保留状态和输出 24 小时」。修法：超过 jobRetention 后，在内存和磁盘上都清掉 Shaped 和 SpillPath（只保留状态元数据直到 forget），补一条测试断言磁盘上的 JSON 不再含有输出。
